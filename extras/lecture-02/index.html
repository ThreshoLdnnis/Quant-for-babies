01 / Why data engineering

模型的起点，是一份可信的数据

假设研究问题是：“过去 20 个有效观测的涨幅较高，未来是否也容易上涨？”看上去只是一个除法，真正运行时却要先回答：股票代码有没有丢掉开头的零？20 行是否按日期排列？有没有把另一只股票接进窗口？除息产生的机械价格变化是否被误认为亏损？今天计算时能否使用这条数据？

金融数据工程是把外部记录转成可供研究使用的数据，并保留每次转换的依据。它不只追求“程序没报错”，还要求数据的含义、时间和来源都正确。输入错误可能得到很漂亮的图，但漂亮不等于可信。

  1. 采集与快照接口参数、原始文件、时间和版本
  2. 检查与清洗字段、类型、主键、缺失与异常
  3. 计算与入库特征、表结构、约束与查询
  4. 验收与交付质量报告、可重跑脚本与说明

同一个研究，数据问题会怎样改变结论？

触发情境错误会传播到哪里正确的工程动作
同一天行情重复两次成交量被重复求和，滚动窗口“20行”实际不足20次观测。定义主键，区分完全重复和数值冲突。
停牌缺行，直接前向填充凭空生成零收益与交易机会，低估波动。先查交易日历和停牌状态，再决定展示或估值口径。
用今天的股票池研究十年前退市股票被排除，产生幸存者偏差。保存历史证券状态与当时可用股票池。
财报只按报告期关联在公告发布前就使用财报数值，产生前视偏差。使用公告时间 / 可用时间，做时点关联。

把数据分层，才能定位问题

Raw 原始层：保存接口返回，不在原地改值。Clean 清洗层：完成类型统一、主键检查与隔离，说明删掉或保留什么。Feature 特征层：在固定清洗快照上计算滞后、均线和收益。Report 报告层：列出行数、规则触发、覆盖范围和验证结论。

这四层不要求购买复杂系统。CSV、一个 SQLite 文件、一个 JSON 报告和脚本就能建立第一版证据链。重要的是不要把“修过的数据”写回原始文件，更不要无记录地手动修改几个异常值。

02 / Data contract

先定义“一行”，再看 OHLCV

本讲日行情表的粒度是：一个股票 × 一个交易日期 × 一个价格口径。离线练习只保存一种原始价口径，因此主键是 (symbol, trade_date)。如果同表存原始价、前复权和后复权，主键必须再包含 adjustment，或分表存放；否则不同口径会互相覆盖。

OHLCV 是 Open、High、Low、Close、Volume 的缩写。它压缩了一天内的交易信息：开盘、最高、最低、收盘和成交量。它不是全天逐笔成交记录，也不能告诉你每个价格上能成交多少。

标准字段含义 / 类型本讲单位与检查
symbol证券标识，字符串保留前导零；生产库宜含交易所，避免跨市场重名。
trade_date行情所属日期日频用 YYYY-MM-DD；不是采集时间，也不是所有自然日。
open / high / low / close开盘 / 最高 / 最低 / 收盘价，数值原始 A 股报价为元/股；价格有限且大于0；high ≥ open、close、low；low ≤ open、close。
volume成交量，数值本讲统一成股；AkShare 此接口返回手，A股一手为100股，需显式乘100。
amount成交额，数值人民币元；与成交量不是同一个字段；非负，保留来源单位。
turnover_rate换手率，可选接口百分数 2.5 表示2.5%；若统一为小数，除以100；分母口径需查来源。
adjustment价格调整口径raw / qfq / hfq；影响所有 OHLC，不能只给 close 复权后混用。
source / fetched_at来源 / 采集时间用来追溯，时间最好含时区；与业务日期分开。

用一根蜡烛理解四个价格

单位错误会造成“程序正确，结果错100倍”

假设接口成交量为 12,000 手，成交额为 12,300,000 元（均为模拟数）。成交股数是 1,200,000 股；成交均价约为 10.25 元/股。如果忘记乘100，就会得到 1,025 元/手，误当成元/股后会夸大100倍。

成交均价 ≈ 成交额 ÷ 成交股数只在字段对应同一市场、同一时段、同一币种，且成交量大于0时使用；价格口径用原始价。

这也给我们一个检查思路：若“成交额 ÷ 成交股数”长期远离当日原始 high/low，优先排查单位和字段映射。但四舍五入、供应商定义及调整口径都可能影响边界，这属于需复核的诊断，不能机械改价。

不要用复权价检查原始成交额。

复权会改变价格刻度，成交量和成交额未必同步调整。把后复权 high/low 与原始成交均价比较，可能把正常记录误判为异常。

03 / Price basis

原始价记录交易，复权价帮助跨期比较

股票发生派息、送转等公司行为后，每股对应的权益可能变化。价格下降不一定等于投资者财富同比例下降。数据工程要同时回答“当时交易报价是多少”和“跨这次事件如何比较收益”，这两个问题需要不同字段。

原始价格 raw

反映历史市场报价，适合核对成交、涨跌停和名义股数。但直接跨除权除息计算，可能产生机械跳点。

复权价格 qfq / hfq

按供应商规则调整历史价格，帮助构建可比序列。前复权常锚定较新价格，后复权常锚定较早价格；应核实具体算法与版本。

先做一个现金分红的模拟手算

假设除息前持有1股，收盘价100元；每股现金分红5元；除息后价格恰为95元。只算价格变动，得到 −5%；若计入收到的5元现金、忽略税费并保持股数不变，总价值仍为100元。本例没有市场波动，也不是对真实股票除息后涨跌的预测。

rprice = Pt / Pt−1 − 1 = 95 / 100 − 1 = −5%
rcash = (Pt + Dt) / Pt−1 − 1 = 0%D 为本期每股现金分红；此简式不覆盖送转股、配股、税费和再投资等复杂情况。

真实金融案例：中国平安的年度派息

中国平安（601318）的2024年年度权益分派公告披露：每股派发现金红利1.62元（含税），A股股权登记日为2025年6月27日，除息和发放日为2025年6月30日。由于回购股份不参与分红，公告用于除息参考价计算的“虚拟分派每股现金红利”约为1.6046元，除息参考价按前收盘价减去该数值计算。查看原始实施公告（PDF）↗

工程启示是：现金派发金额与除息参考价格调整数值，并不必然相等。公告参考价也不是当天实际成交价。本页没有填入真实6月30日收盘价或涨跌幅。你可以在联网选做中采集这一时段，将真实接口记录与公告事件表关联后再分析。

研究时必须保留的边界

  • AkShare 提醒：前复权历史会随新的除权除息重算，甚至可能出现负值。不能把“复权价一定为正”作为通用规则。本讲的正价格检查只用于原始价模拟表。
  • 后复权价格的数值尺度可能很大。复权价格不是历史实际成交报价，也不能直接替代税后现金账户与交易成本计算。
  • 相同代码、相同日期、不同采集日可能返回不同前复权历史。复现研究需要冻结原始文件、调整口径、接口版本、采集时间与哈希值。
  • 只下载当前幸存的股票，或用当前财报和行业标签补历史，即使价格已复权，也仍然可能有研究偏差。

标准化字段时，单位要写进转换规则

rename_map = {"日期": "trade_date", "开盘": "open", "最高": "high",
              "最低": "low", "收盘": "close", "成交量": "volume",
              "成交额": "amount"}                   # 1. 固定映射
df = raw.rename(columns=rename_map)[list(rename_map.values())].copy()
df["symbol"] = "601318"                             # 2. 接口按单股取数，补上代码
df["trade_date"] = pd.to_datetime(df["trade_date"], errors="raise")
for col in ["open", "high", "low", "close", "volume", "amount"]:
    df[col] = pd.to_numeric(df[col], errors="raise")  # 3. 明确数值列
df["volume"] = df["volume"] * 100                    # 4. 手 → 股
df = df.sort_values(["symbol", "trade_date"]).reset_index(drop=True)

第1行建立来源字段与内部字段的对应关系，挑出需要的列，不把所有上游列都当成稳定接口。第2行补代码，不从数值型股票代码猜前导零。第3步使用 errors="raise"，遇到脏字符立即停下。第4步只做一次单位转换；应在元数据中记录转换前后单位，避免重复乘100。最后用股票与日期排序。

完整采集脚本比短例多做了什么？

  • 分别请求 raw 与 hfq，分文件保留，避免混合口径；不对已有目录静默覆盖。
  • 记录股票、起止日、频率、价格调整、来源、UTC采集时间、Python / pandas / AkShare版本。
  • 对每份 CSV 记录行数和 SHA-256，帮助判断两次研究是否使用同一快照。
  • 检查空表、字段变化和重复日期；请求失败直接报错。它不自动证明行情正确，后续仍须质量检查。
请求失败时怎么处理？

先保留报错，检查网络、参数、接口文档和版本；不要把空表补成零价格，不要无限重试。若要批量采集，设置有限重试、等待间隔与失败清单，成功文件缓存复用。课程可继续走离线路线，无需把模拟文件改名成真实行情。

06 / First inspection

读取表格，先确认类型与覆盖范围

07 / Cleaning policy

清洗不是“删到没有报错”

数据清洗最关键的部分是决策：什么确定是错误，什么只是可疑？本讲离线脚本使用保守规则：无法解析、关键值缺失或逻辑不可能的记录进入隔离表；完全相同的重复保留一份；同股同日数值冲突的记录全部隔离。这样我们可以从质量报告追查每一行去了哪里。

先排序，再辨认重复，但别用排序替代证据

key = ["symbol", "trade_date"]
value_cols = key + ["open", "high", "low", "close", "volume", "amount"]
exact = df.duplicated(subset=value_cols, keep="first") # 1. 完全相同的额外副本
exact_rejects = df.loc[exact].copy()                   # 2. 留下隔离证据
unique_rows = df.loc[~exact].copy()
conflict = unique_rows.duplicated(subset=key, keep=False)
conflict_rejects = unique_rows.loc[conflict].copy()     # 3. 冲突键的全部行
candidate = unique_rows.loc[~conflict].copy()
candidate = candidate.sort_values(key).reset_index(drop=True)

duplicated(..., keep="first") 把完全相同的第二份及以后标为 True。~ 是取反，.loc[条件] 按条件选行。去掉精确副本后，再按业务主键找冲突；keep=False 将冲突的两份都标出来。copy() 明确产生独立结果，避免边修改边引用原表。

如果供应商明确提供修订版本、发布时间或优先级，才可按书面规则选择最新有效版本，并保留旧版。随手 drop_duplicates(key, keep="last") 只意味着“保留文件里碰巧排最后的那行”，不能证明那行更正确。

关键值、OHLC 与非有限数

numeric = ["open", "high", "low", "close", "volume", "amount"]
for col in numeric:
    candidate[col] = pd.to_numeric(candidate[col], errors="coerce")
required_missing = candidate[key + numeric].isna().any(axis=1)
finite = candidate[numeric].apply(
    lambda col: col.map(lambda x: pd.notna(x) and float("-inf") < x < float("inf"))
).all(axis=1)
positive_price = (candidate[["open", "high", "low", "close"]] > 0).all(axis=1)
ohlc_ok = (candidate["high"] >= candidate[["open", "close", "low"]].max(axis=1)) & (
    candidate["low"] <= candidate[["open", "close"]].min(axis=1))
nonnegative = (candidate[["volume", "amount"]] >= 0).all(axis=1)
valid = ~required_missing & finite & positive_price & ohlc_ok & nonnegative
rejected = candidate.loc[~valid].copy()
clean = candidate.loc[valid].sort_values(key).reset_index(drop=True)

errors="coerce" 把无法解析的数值变成缺失，方便统一识别；生产脚本要先保存原始字符串及行号。any(axis=1) 问“这一行是否至少一列缺失”；all(axis=1) 问“这一行是否所有列都满足”。无限大也是错误，即使它不是 NaN。OHLC检查允许平盘和一字价，比较用 ≥ / ≤。最后把无效行与有效行分开。完整实验还记录具体原因；不要只保留一个总布尔值。

缺失、停牌和零成交量，必须分开理解

观察到的现象可能原因可采取的动作不要直接做
日期不在交易日历周末、法定休市作为非交易日处理，不生成行情。按自然日插值生成价格。
市场开市，个股缺行停牌、未上市、退市、漏采或来源遗漏关联当时证券状态与停牌表；未确认前标记原因未知。仅凭缺行就断言停牌。
关键 close 缺失解析或上游数据问题隔离，重新获取并核对来源。将它填成0或用未来价格回填。
volume = 0特定状态记录、供应商补行联查来源定义、停牌状态和 amount，明确是否可交易。把“有价格”当成“可成交”。

用于持仓估值时，研究者可能按已声明规则沿用最近可用价格，同时把 is_tradable=False；这与创建一条可供下单的真实行情不同。停牌期间能否交易、复牌后收益归属和风险统计，应在回测层再作明确处理。

异常收益：先标记调查，别自动截断

某日价格跳变可能来自错价、除权除息、合并重组、上市初期或真实市场变化。固定的“超过10%就是错”不适用于所有市场、板块和历史时期。本讲可设置一个诊断阈值，例如绝对观测间收益超过30%时加入待复核清单；它不是现行涨跌停规则，更不应自动删掉或缩尾。

清洗也会制造偏差

只保留“看上去正常、一直交易、未来未退市”的股票，会让样本更容易取得好结果。每条排除规则都要说明经济原因、影响行数和对研究结论的可能影响。

08 / Features without leakage

groupby、shift、rolling：让计算留在正确时间线上

这三个工具可以读成一句话：先按股票分组，再向后看，最后在历史窗口内计算。执行前必须确认主键唯一、日期有效并已排序。否则公式正确，窗口里装的仍可能是错误的记录。

1. groupby：把不同股票的计算隔开

clean = clean.sort_values(["symbol", "trade_date"]).reset_index(drop=True)
g = clean.groupby("symbol", sort=False)              # 1. 每只股票一组
summary = g.agg(n_obs=("close", "count"),             # 2. 每组有效价格数
                first_date=("trade_date", "min"),
                last_date=("trade_date", "max"),
                total_volume=("volume", "sum"))
print(summary)

sort=False 控制分组键的排序，不负责整理每组内的日期；前面的 sort_values 才负责时间顺序。agg 把多行聚合成每股一行，给结果起易懂的列名。成交量按组求和有意义，而“收盘价求和”通常不对应你想要的金融问题。

2. shift：拿到这只股票的上一条已知记录

clean["prev_close"] = g["close"].shift(1)             # 1. 组内向后移动一行
clean["prev_date"] = g["trade_date"].shift(1)
clean["return_observed"] = clean["close"] / clean["prev_close"] - 1
print(clean[["symbol", "trade_date", "close", "prev_close", "return_observed"]])
rt = Pt / Pprev − 1prev 指同一股票上一条有效观测。它只有在数据连续覆盖交易日时，才可解释为相邻交易日价格收益。

shift(1) 将上一行价格对齐到当前行。每只股票首行没有前值，应保留缺失，不能填0。105除以100减1得到0.05，即5%，不是5。缺口前后这两条记录之间的收益可能跨多个交易日；应通过交易日历另行识别，而不是把它冒称单日收益。

3. rolling：只使用窗口内的历史

clean["ma5"] = clean.groupby("symbol")["close"].transform(
    lambda s: s.rolling(window=5, min_periods=5).mean())
clean["ma20"] = clean.groupby("symbol")["close"].transform(
    lambda s: s.rolling(window=20, min_periods=20).mean())
clean["momentum_20obs"] = clean["close"] / clean.groupby("symbol")["close"].shift(20) - 1
# 在 t 日收盘后才能确认的 ma5，最早留到下一条观测作信号演示
clean["ma5_lag1"] = clean.groupby("symbol")["ma5"].shift(1)
  1. transform 让每组计算的结果保持与原表同样长度和索引，减少直接 groupby().rolling() 产生多层索引后的误对齐。
  2. lambda s: 定义“对这一组价格 s 做什么”；窗口5表示最近5条观测，包含当前行。min_periods=5 要求完整窗口，前4条留空。
  3. MA20需要20个价格；20期动量 P_t/P_(t−20)−1 需要21个价格。两者的起始位置不同，别因为都含20就当作同一种边界。
  4. ma5_lag1 将收盘后已知指标向后移一条观测，示意时间对齐；它不保证能在下一次开盘成交。真实回测还需交易日历、信号时间、停牌与撮合规则。
MAn,t = (Pt + Pt−1 + … + Pt−n+1) / n本讲 n 为观测数；整数窗口与按时间跨度的 rolling("20D") 含义不同，20个自然日也不同于20个交易日。

常见错误：直接 clean["close"].shift(1)

全表 shift 会在 SIM002 首行接到 SIM001 的最后价格，造成跨股票收益。全表 rolling 也会把两只股票混入同一个均线窗口。只要一张表有多只股票，就先按 symbol 分组；每次计算后检查每组首行的前值是否为缺失。

9.1 先确定“一行是什么”

这张行情表的粒度是一只股票、一个交易日期、一种已经确定的价格口径。例如同一日期可以同时存在 SIM001 和 SIM002，但同一只股票同一天不能出现两行。这个约定比表名更重要，因为所有统计都建立在它上面。

表一行的含义唯一标识用途
prices某只股票某天的模拟原始日线(symbol, trade_date)收益、均线、成交额与数据质量
securities一只虚构证券的描述symbol名称、行业等说明字段

主键（PRIMARY KEY）可以理解为每一行的身份证。这里用两列共同组成主键：仅用日期会把不同股票挤在一起，仅用代码又无法保存多天行情。在真实研究库里，如果同表容纳多个数据源、复权口径或修订版本，唯一键还需要包括相应的维度；本课程通过“一次离线运行只含一种口径”简化问题。

-- 01 股票说明表：每个代码最多对应一行
CREATE TABLE IF NOT EXISTS securities (
    symbol TEXT NOT NULL PRIMARY KEY,
    name TEXT NOT NULL,
    industry TEXT
);

-- 02 行情表：价格为正，数量非负，交易日必须有值
CREATE TABLE IF NOT EXISTS prices (
    symbol TEXT NOT NULL,
    trade_date TEXT NOT NULL,
    open REAL NOT NULL CHECK (open > 0),
    high REAL NOT NULL CHECK (high > 0),
    low REAL NOT NULL CHECK (low > 0),
    close REAL NOT NULL CHECK (close > 0),
    volume REAL NOT NULL CHECK (volume >= 0),
    amount REAL NOT NULL CHECK (amount >= 0),
    PRIMARY KEY (symbol, trade_date),
    CHECK (low <= open AND low <= close),
    CHECK (high >= open AND high >= close AND high >= low)
);

-- 03 跨股票按日期查询时可使用这个索引
CREATE INDEX IF NOT EXISTS idx_prices_date ON prices(trade_date);
  1. 01：TEXT 保存代码、名称和行业。代码使用字符串，才能保留 A 股代码开头的零。industry 允许未知，未知应写成 NULL，而非凭空编一个行业。
  2. 02：REAL 用于本课的浮点计算，NOT NULL 拒绝缺失关键字段，CHECK 拒绝价格小于等于零、负成交量和不可能的最高最低价组合。日期统一保存为 YYYY-MM-DD 文本，这样同格式字符串的顺序与日期顺序一致；日期合法性仍在清洗阶段验证。
  3. 复合主键：重复插入同一个代码与日期会报错。不要用 INSERT OR IGNORE 把冲突静默吞掉，也不要把未经检查的 to_sql(if_exists="replace") 用在已有约束的正式表上；后者会重建表，可能失去原有约束。
  4. 03：索引像书的目录，能帮助定位记录，也占用空间并增加写入成本。主键已经覆盖以代码开头的定位，本课额外演示日期索引；真实项目应结合查询方式和执行计划决定，不需要给每列都建索引。

以上展示核心教学结构；完整实操还保存 adjustment、source 和 is_simulated，并约束模拟数据标识、原始价口径及证券外键。已有实操数据库可以直接运行后续查询，不需要重建表。SQLite 的列类型与约束有自己的规则；本课把关键列明确写为 NOT NULL，不依赖“主键名字听起来就一定不为空”的直觉。进一步阅读：SQLite 建表与约束文档。

9.2 SELECT：像提问一样写查询

先把问题用中文说完整：“找出 SIM001 在指定日期内的行情，只看日期、收盘价与成交量，按日期从早到晚排列。”然后再逐句翻译。SELECT 选列，FROM 指定表，WHERE 筛行，ORDER BY 排序。

-- 01 只取本问题需要的列
SELECT symbol, trade_date, close, volume
-- 02 指定行情表
FROM prices
-- 03 先选择股票，再选择日期范围；BETWEEN 包含两个端点
WHERE symbol = 'SIM001'
  AND trade_date BETWEEN '2024-01-01' AND '2024-02-29'
-- 04 显式排序，不依赖数据库碰巧返回的顺序
ORDER BY trade_date ASC;

逐行理解：01 决定输出列，不改变底层数据；02 告诉数据库去哪里找；03 要求条件同时成立，字符串用单引号；04 的 ASC 是升序，换成 DESC 即倒序。不写 ORDER BY 时，不能把返回顺序当作时间顺序；这对收益计算尤其关键。查询返回零行通常先检查代码、日期格式和数据覆盖范围，不要立刻认定接口失效。

在 Python 中把用户输入传给查询时，使用参数占位符。参数是“数据”，不应该被拼接成 SQL 语法。

# 01 con 是已打开的 sqlite3 连接
sql = "SELECT trade_date, close FROM prices WHERE symbol = ? ORDER BY trade_date"
# 02 逗号让括号中的一个值构成单元素元组
rows = con.execute(sql, ("SIM001",)).fetchall()
# 03 只展示前五行，避免把全部结果挤满屏幕
print(rows[:5])

逐行理解：01 的问号是值的位置，不是列名或表名的位置；02 由数据库驱动处理引号与类型，("SIM001",) 末尾的逗号不可省略；03 展示查询结果的切片。用 f-string 拼接代码或日期会带来引号错误与注入风险。表名若要动态选择，应使用程序预先允许的名单，不能用一个问号代替表名。

9.3 GROUP BY：把每天的行归纳成每只股票的统计

现在换一个问题：“每只股票有多少条有效记录，覆盖哪些日期，平均日成交额是多少？”查询的粒度从“股票×日期”变成了“股票”。GROUP BY 会把同一股票的多行放进一组，再让 COUNT、MIN、MAX、AVG 对每组计算。

-- 01 每只股票输出一行，给计算结果起一个清晰名字
SELECT symbol,
       COUNT(*) AS n_rows,
       COUNT(amount) AS n_amount,
       MIN(trade_date) AS first_date,
       MAX(trade_date) AS last_date,
       AVG(amount) AS avg_amount
-- 02 WHERE 在分组之前筛选原始行
FROM prices
WHERE trade_date >= '2024-01-01'
-- 03 按代码形成分组
GROUP BY symbol
-- 04 HAVING 在分组之后筛选统计结果
HAVING COUNT(*) >= 20
-- 05 稳定排序；平均成交额相同时用代码决定先后
ORDER BY avg_amount DESC, symbol ASC;

逐行理解：01 中 COUNT(*) 数所有行，COUNT(amount) 只数成交额不为 NULL 的行；本课干净表要求成交额不为空，两者应相等。02 把研究区间限制在分组前；03 决定一组是什么；04 只留下至少有 20 行的股票；05 决定展示顺序。AS 只是给结果起别名，不会修改原表字段。

NULL 不是零，也不是空字符串。NULL 表示未知或缺失；用 IS NULL 检查，不能写 = NULL。AVG、SUM 等聚合通常跳过 NULL，因此均值必须同时报告有效样本数。把缺失成交额直接填零，会把“没有拿到数据”写成“当天没有成交”，改变结论。

不要写 SELECT symbol, trade_date, AVG(close) FROM prices GROUP BY symbol，再把输出日期误认为均值对应的日期。一个股票组中有许多日期，未被分组或聚合的日期没有明确统计含义。若目标是“最新收盘价”，应该使用下一节的行排名；若目标是“区间均价”，就清楚命名为区间均价。跨股票比较价格水平通常也没有直接的投资意义；这里的 SQL 练习是在学习查询，不是在证明某只股票更值得买。

WHERE 回答“哪些原始行参加计算”，HAVING 回答“哪些分组结果值得保留”。例如筛选成交额大于某值的日子，应放 WHERE；筛选平均日成交额大于某值的股票，应放 HAVING。两者交换位置会回答不同的问题。

9.4 LEFT JOIN：把名字接上，也把未知保留下来

行情表专心保存数值，证券说明表保存名称和行业。要做一张“行情+名称”的表，需要按代码连接。左连接会保留左表的每一行：右表找不到代码时，名称与行业返回 NULL，让缺口暴露出来，而不是悄悄让行情消失。

-- 01 p 和 s 是两张表的短别名，用来说明字段来自哪里
SELECT p.symbol, p.trade_date, p.close,
       s.name, s.industry
-- 02 prices 放在左侧，它的行需要保留
FROM prices AS p
-- 03 按证券代码匹配右表，匹配不到时右侧字段为 NULL
LEFT JOIN securities AS s ON p.symbol = s.symbol
-- 04 这里只筛左表条件，不把缺失的右表记录排除
WHERE p.trade_date >= '2024-01-01'
ORDER BY p.symbol, p.trade_date;

逐行理解：01 选取想要的数值与说明字段；02 确定保留的是行情；03 声明连接键；04 只限制行情日期。若加上 WHERE s.industry = '示例行业'，未知行业行会被筛掉，因为 NULL 不能满足这个条件。如果目的是“仍保留所有行情，只匹配某类右表记录”，应把右表限制写进 ON 条件，并明确此时未匹配与不属于该行业都会显示为空。若目的是确实只研究某行业，则 WHERE 是有意的筛选，需要报告样本变化。

另一个危险比漏行更隐蔽：右表如果同一代码有两行，左表每一条行情就可能被复制两遍，成交额汇总也随之翻倍。连接前先检查键唯一，连接后再检查行数与键唯一。不要用 DISTINCT 随手抹平连接问题，因为它可能同时掩盖了错误的表粒度。

-- 01 右表代码唯一时，这个检查应返回零行
SELECT symbol, COUNT(*) AS n
FROM securities
GROUP BY symbol
HAVING COUNT(*) > 1;

-- 02 量化统计连接后仍缺少说明的行情行数
SELECT COUNT(*) AS unmatched_rows
FROM prices AS p
LEFT JOIN securities AS s ON p.symbol = s.symbol
WHERE s.symbol IS NULL;

逐行理解：01 每个代码计数并挑出重复者；若已建立正确主键，重复写入会先被拒绝，这仍是检查外部说明表的好习惯。02 用右表主键是否为空判断是否匹配，返回的是“行情行数”，不是“缺失证券数量”。如要数证券，把 SELECT 改为 COUNT(DISTINCT p.symbol)。历史行业还涉及生效日期；用今天的行业表解释过去，仅适合作为当前描述，不等于当时已知的分类。连接语义可查阅 SQLite SELECT 文档。

9.5 LAG：在每只股票内部拿到上一条记录

普通分组把许多行压成一行，而窗口函数保留原来的每一行，同时让这一行“看见”同一分组内的其他记录。LAG(close) 在有序窗口里取上一条收盘价；它相当于前面 pandas 中分组后的 shift(1)。

-- 01 CTE 是有名字的中间查询，先把上一条价格算出来
WITH lagged AS (
    SELECT symbol, trade_date, close,
           LAG(close) OVER (
               PARTITION BY symbol ORDER BY trade_date
           ) AS prev_close
    FROM prices
)
-- 02 在外层使用中间结果，明确处理第一条和零分母
SELECT symbol, trade_date, close, prev_close,
       CASE WHEN prev_close > 0
            THEN 1.0 * close / prev_close - 1.0
            ELSE NULL END AS price_return
FROM lagged
-- 03 日期筛选放在窗口计算之后，保留区间第一天的历史参照
WHERE trade_date BETWEEN '2024-01-01' AND '2024-02-29'
ORDER BY symbol, trade_date;
  1. 01：WITH lagged AS (...) 给中间查询命名。PARTITION BY symbol 为每只股票分开计算，ORDER BY trade_date 指定过去到现在的顺序；两者少一个，结果就可能错。
  2. 02：当某只股票没有更早记录时，上一价为 NULL，收益也应为 NULL。1.0 * 明确启用浮点运算，避免某些整型输入的除法截断；CASE 防御零或异常分母。主表已有正价格约束，但公式本身仍清楚表达有效条件。
  3. 03：先计算历史上的上一价，再选择展示区间。如果先把日期截断，再算 LAG，区间第一条会丢失原本存在的上一价。股票筛选可提前做，因为分组相互独立；日期边界则需要根据所需历史长度谨慎处理。
上一条记录不自动等于上一个交易日。如果某天缺行情、停牌或被隔离，LAG 会跳到更早的有效记录。此时算出的是相邻有效观测间的价格变化，不应未经核验就标成严格“单日收益”。需要连接交易日历、确认停牌状态，并给间隔异常加标记；不能把缺失值随意补上来凑齐天数。

公式是 price_return = close / prev_close − 1。它没有把分红再投资、滑点、佣金或不能成交的情况放进去。因此 pandas 与 SQL 算得一致，证明的是两套实现的一致性，并不能独立证明价格口径或交易假设正确。

9.6 ROW_NUMBER：准确找出每只股票的最后一行

想取“每只股票最新日期的收盘价”，不能写 MAX(trade_date), MAX(close)：最高价可能出现在另一日。我们要找的是一整行，而不是两个分别求出的最大值。

-- 01 在每个股票分组内，按日期倒序编号
WITH ranked AS (
    SELECT symbol, trade_date, close,
           ROW_NUMBER() OVER (
               PARTITION BY symbol ORDER BY trade_date DESC
           ) AS rn
    FROM prices
)
-- 02 外层挑出每组编号为 1 的那一整行
SELECT symbol, trade_date, close
FROM ranked
WHERE rn = 1
ORDER BY symbol;

逐行理解：01 的倒序让最新日期排在第一，ROW_NUMBER 依次赋值 1、2、3；复合主键确保同一股票日期不重复，所以排序有明确结果。02 在外层筛选编号，输出的日期与收盘价来自同一条记录。窗口函数不能直接放在 WHERE 中筛选，因此本课统一采用 CTE 再外层筛选；这也让查询更容易检查。若真实表包含多个修订版本，必须先定义取哪一版，或给排序补充稳定且有业务意义的版本键。参见 SQLite 窗口函数文档。

到这里，Python 与 SQL 的关系就清楚了：Python 便于组织采集、清洗、文件与图表；pandas 便于对内存中的表操作；SQL 便于从保存下来的表里筛选、连接与计算。选择工具时先写明研究问题、表粒度、时间范围和价格口径，再决定如何实现。

练习 2：用 SQL 做一个不会漏行的证券说明连接

FROM prices AS p
LEFT JOIN securities AS s ON p.symbol = s.symbol
ORDER BY p.symbol, p.trade_date;

FROM prices AS p

练习 3：找出每只股票最新行情，并解释一个错误答案

练习 4：检查相邻观测收益，而不是被漂亮小数说服

运行 LAG 查询，用 pandas 的分组 shift 独立计算对应收益。比较时先按代码和日期对齐，再处理缺失值。请说明：为什么不应该先把整张表的首尾行删掉，再比较两个数组？为什么一只股票出现日期缺口时，不能直接把跨缺口变化叫作单日收益？

展开参考思路与评分标准

应按 (symbol, trade_date) 一对一连接两套结果，检查键集合相同，再检查两侧缺失位置一致，并对有效值使用浮点容差。整表删一行只删掉全局第一条，无法正确处理每只股票各自的首条；按位置比较还可能让不同代码或日期碰到一起。跨缺口收益覆盖多个观测间隔，需要交易日历与状态证据来确认间隔含义。

预期性质：每只股票第一条没有上一价；不存在跨股票取值；两套结果的有效值在约定容差内一致。评分 10 分：键对齐 3 分，缺失位置 2 分，浮点比较 2 分，时间间隔解释 3 分。仅展示“数值看起来差不多”不能得满分。

本讲总结：可靠的数据，才有可检验的因子

这节课的终点不是下载成功，也不是写出一条 SQL。你已经把金融语义、程序操作和研究证据连在一起：先定义字段与口径，再保留原始输入；通过清洗和隔离建立可解释的数据层；按股票、时间计算特征；用主键与约束保存；通过独立查询交叉检查。
